# 심사기준 분석 — 어디서 점수를 따는가

공식 심사 기준은 **① 게임 완성도 ② 용량 준수 ③ 재미** 세 가지다.
가중치는 공개되지 않았으므로 균등(1:1:1)이라 가정하고, **어느 항목이 통제 가능한가**로 우선순위를 정한다.

## ① 게임 완성도 — 가장 통제하기 쉬움. 여기서 이긴다

이런 공모전에서 탈락하는 작품의 대부분은 "재미없어서"가 아니라 **미완성이라서**다.
게임잼 출품작 중 다수는 타이틀 없음 / 엔딩 없음 / 크래시 / 조작 설명 없음 상태로 제출된다.

**완성도 = 게임플레이 루프가 아니라 "제품의 껍데기"에서 결정된다.**

필수 체크:
- [ ] 타이틀 화면 (게임 이름 + 시작 + 조작법 + 종료)
- [ ] 게임 내 조작법 안내 (별도 txt에 의존 금지)
- [ ] 일시정지 / ESC로 안전 종료
- [ ] 명확한 승리 조건과 **엔딩 화면**
- [ ] 게임오버 → 재시작 루프 (프로그램 재실행 없이)
- [ ] 점수/기록 표시, 가능하면 로컬 최고기록 저장
- [ ] 사운드 On/Off 토글 (심사자가 조용히 볼 수도 있다)
- [ ] 창 모드 기본, 리사이즈/전체화면 시 깨지지 않기
- [ ] **첫 실행부터 크래시 0회** — 깨끗한 VM에서 검증 (`07-제출체크리스트.md`)

## ② 용량 준수 — Pass/Fail. 실수하면 그냥 탈락

- 이건 점수가 아니라 **자격 요건**에 가깝다. 초과하면 심사조차 안 된다.
- 다만 "여유롭게 지킨 것"이 가산점이 될 수 있다. 700KB로 만든 게임은
  1,470,000 바이트로 만든 게임보다 공모전 취지에 부합한다는 인상을 준다.
- **전략: 목표 1,400,000 바이트. 달성하면 남은 예산을 콘텐츠에 재투자.**
- 빌드 때마다 자동 용량 체크 스크립트를 CI/빌드 스크립트에 넣는다. (`05-용량예산.md`)

## ③ 재미 — 가장 통제하기 어려움. "첫 60초"에 올인

심사자는 수십 개 작품을 돌려본다. **처음 1분 안에 재미가 전달되지 않으면 끝이다.**

- 튜토리얼 스테이지 금지. **1스테이지 자체가 튜토리얼**이 되게 설계.
- 실행 → 3초 내 조작 가능. 로딩·인트로 컷신 금지.
- 1판 길이 **2~5분**. "한 판 더" 유도.
- 난이도 곡선: 처음 30초는 거의 못 지게, 이후 급격히 조인다.
- 손맛(게임필): 화면 흔들림, 히트스톱, 파티클, 사운드 피드백.
  **이건 용량을 거의 안 먹으면서 체감 퀄리티를 가장 크게 올리는 항목이다.**

## 명시되지 않았지만 실제로 점수에 반영되는 것

| 요소 | 이유 |
| --- | --- |
| **1.44MB라는 제약의 활용** | 플로피/레트로 감성, 도트, 칩튠은 주제와 서사가 맞아떨어져 심사자에게 어필 |
| **오리지널리티** | 어디서 본 게임의 복제는 완성도가 높아도 상위권에서 밀린다 |
| **기술적 자랑거리** | "절차적 생성으로 300KB에 100스테이지" 같은 한 줄 스토리 |
| **제출물의 정돈됨** | 스크린샷, GIF, 한 문단 설명 — 심사자가 이해하기 쉽게 |
| **전시 적합성** | 제출 폼 명시: **수상작은 2P GAME ARCADE 전시회·행사에 전시될 수 있음** |
| **언어 접근성** | 한/영/일 3개 국어 공모전 = 심사자가 한국어 화자가 아닐 수 있음 |

### 전시 적합성 — 폼에서 확인된 숨은 기준

제출 폼의 동의 항목에 *"수상작은 향후 개최되는 2P GAME ARCADE 전시회 및 행사 등에
전시될 수 있습니다"*가 명시돼 있다. 즉 심사자는 무의식적으로
**"이걸 전시장 부스에 놓을 수 있나"**를 평가한다. 아케이드 부스에서 잘 굴러가는 게임의 조건:

- [ ] **게임패드 지원** (전시장은 키보드/마우스가 없을 수 있다) — 최소한 키보드 전용은 되게
- [ ] **마우스 없이 100% 플레이 가능** (메뉴 포함)
- [ ] **어트랙트 모드 / 자동 리셋** — 일정 시간 무입력 시 타이틀로 복귀
      → 다음 관람객이 항상 처음부터 시작할 수 있다. **구현 30분, 인상은 프로급**
- [ ] **1판이 짧다 (2~5분)** — 줄 선 관람객이 돌아가며 할 수 있는 길이
- [ ] **전체화면 지원** + 화면 비율 깨지지 않음
- [ ] **설명 없이 이해 가능** — 옆에 사람이 붙어 설명해줄 수 없다
- [ ] 세이브 의존 없음 (재부팅해도 항상 같은 상태로 시작)

> 이건 명시된 심사 기준은 아니지만, **완성도 항목에서 티가 나는 차이**를 만든다.

### 언어 접근성

한/영/일 3개 국어로 운영되는 국제 공모전이므로 심사자가 한국어 화자가 아닐 수 있다.

- **게임 내 텍스트는 영어 기본** 또는 아이콘·픽토그램 중심의 언어 비의존 설계
- 덤으로 **한글 폰트를 안 넣어도 되어 용량이 크게 절약된다** (`05-용량예산.md`)
- 제출 폼의 Game Description도 **영어(+한국어 병기)**로 작성

## 결론 — 점수 배분 전략

```
완성도  : 무조건 만점 목표.   (통제 가능, 노력 = 점수)
용량    : Pass 확보 + 여유.   (엔진 선택으로 이미 결판)
재미    : 첫 60초에 집중.     (스코프를 줄여 폴리싱 시간 확보)
```

**즉, "작고 완성도 높은 게임" > "크고 야심찬 미완성 게임". 스코프를 계속 줄여라.**
