# 개발 환경 — 이중 타깃 워크플로

확정: 2026-08-07 (D-28)

| 역할 | 머신 | 용도 |
| --- | --- | --- |
| **개발기** | **MacBook M4 (arm64)** | 코딩, 플레이테스트, 빠른 이터레이션 |
| **검증기** | **Windows 데스크탑** | 제출 빌드 실행 검증, 게임패드/전체화면, 최종 용량 측정 |

소스는 하나(C + raylib). raylib이 크로스 플랫폼이라 **같은 `main.c`에서 두 산출물이 나온다.**

```
main.c ─┬─→ zig cc -target aarch64-macos       → game      (개발용, 매일)
        └─→ zig cc -target x86_64-windows-gnu  → game.exe  (제출용, 심사 대상)
```

`zig`는 macOS arm64에서 그대로 돌고, Windows 크로스컴파일도 동일하게 된다.
**툴체인 하나로 두 타깃을 모두 커버한다.**

---

## 절대 원칙

> ### 🔴 심사 대상은 **Windows 빌드**다. macOS 빌드는 개발 편의용일 뿐이다.

- **용량 리포트는 반드시 Windows 산출물 기준으로 잰다.** macOS 바이너리는 크기가 다르고
  심사 대상이 아니다. `check-size.sh`는 Windows 산출물에만 건다. (`05-용량예산.md`)
- **"맥에서 잘 돌아간다"는 아무것도 보증하지 않는다.**

| 항목 | 주기 |
| --- | --- |
| macOS 네이티브 빌드 + 플레이 | 상시 (개발 루프) |
| **Windows 크로스 빌드 (컴파일만)** | **매일** — 컴파일 에러·용량 회귀를 즉시 잡는다 |
| **Windows 데스크탑에서 실제 실행** | **주 1회 이상**, D-7부터는 **매일** |

> ⚠️ **Windows 데스크탑은 "클린 머신"이 아니다.** 평소 쓰는 PC에는 각종 런타임이 이미
> 깔려 있어서 DLL 누락을 못 잡는다. **최종 검증은 새 사용자 계정이나 깨끗한 VM에서** 할 것.

## macOS(M4)에서 개발할 때 주의할 함정

Windows에서만 터지고 macOS에서는 안 잡히는 것들:

1. **파일시스템 대소문자 구분** — macOS 기본(APFS)은 대소문자를 **무시**한다.
   `LoadTexture("Player.png")`가 맥에서는 `player.png`도 열지만 Windows에서도 열린다.
   반대로 **Linux 심사자는 없으니** 이건 상대적으로 덜 위험하다. 그래도 **파일명은 전부 소문자**로 통일해 사고를 원천 차단한다.
2. **경로 구분자** — 코드에 `/`만 쓴다. Windows도 `/`를 받아준다. `\`를 쓰면 맥에서 깨진다.
3. **에셋 누락** — 맥 개발 폴더에는 있는데 Windows 배포 ZIP에 안 담기는 사고.
   → **배포 폴더를 매번 새로 만들어** 빌드하고, 그 폴더만 압축한다.
4. **arm64 vs x64 정렬/엔디안** — 둘 다 리틀엔디안이라 엔디안 문제는 없지만,
   구조체 정렬이 다를 수 있다. **바이너리 에셋 포맷을 자작한다면** `#pragma pack`으로 고정하거나
   바이트 단위로 직렬화한다.
5. **부동소수점 미세 차이** — 절차적 생성에 float을 쓰면 시드가 같아도 맥/윈도우 결과가
   갈릴 수 있다. **레벨 생성은 정수 연산 기반으로** 짜는 편이 안전하다.
6. **macOS OpenGL은 deprecated**다 (GL 4.1까지만). raylib GL3.3은 정상 동작하지만,
   **셰이더를 쓴다면 GLSL 버전 지시자 차이**에 주의. raylib이 대부분 흡수해준다.

## macOS 네이티브 빌드 커맨드

```bash
S=raylib-5.5/src
zig cc -target aarch64-macos -Os \
  -I$S -I$S/external/glfw/include \
  -DEXTERNAL_CONFIG_FLAGS -include cfg/config.h \
  -DPLATFORM_DESKTOP -DGRAPHICS_API_OPENGL_33 \
  main.c $S/{rcore,rshapes,rtextures,rtext,raudio,utils,rglfw}.c \
  -o game \
  -framework Cocoa -framework IOKit -framework CoreVideo -framework OpenGL
```

> macOS는 `rglfw.c`를 포함한다 (GLFW 백엔드). RGFW는 Windows에서 크래시했으므로
> 양쪽 모두 GLFW로 통일한다. (`08-엔진실측결과.md`)

Windows 빌드 커맨드는 `08-엔진실측결과.md`의 "재현 방법" 참고.

## 권장 빌드 스크립트 구조

```
build.sh          # ./build.sh mac | win | both
tools/check-size.sh   # Windows 산출물 전용 용량 게이트
dist-win/         # Windows 배포 폴더 (매번 새로 생성 → 이것만 압축)
dist-mac/         # 개발용, 제출과 무관
```

`build.sh win`이 끝나면 자동으로 `check-size.sh dist-win`을 호출해
**1,474,560 초과 시 빌드를 실패**시킨다.
