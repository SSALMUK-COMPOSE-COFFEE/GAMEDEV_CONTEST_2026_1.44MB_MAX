### 이 폼이 알려주는 것 — 전략적 시사점

1. **업로드 상한 10MB / 5개 파일 → 용량 걱정 없음.**
   우리 게임은 최대 1.44MB이므로 여유가 압도적이다.
   → **남는 4개 슬롯을 활용하라.** 게임 ZIP 외에 스크린샷·플레이 GIF·소개 이미지를
   **별도 파일로** 올릴 수 있다. 심사자에게 게임을 이해시킬 유일한 추가 수단이다.
   ⚠️ **단, 홍보용 파일을 게임 ZIP 안에 넣으면 안 된다** — 1.44MB에 합산될 수 있다.
   반드시 **별개 파일로 분리**해서 업로드할 것.

2. **소스코드 제출 의무 없음.** 폼에 해당 문항이 없다.
   단, 규칙 02(공고일 이후 신규 제작) 소명 요구에 대비해 git 히스토리는 유지한다.

3. **플랫폼 제한 없음 (Windows/Mac/Linux 모두 가능).**
   → 그래도 **Windows 단일 빌드 권장.** 멀티 플랫폼 빌드를 한 ZIP에 넣으면
   1.44MB에 전부 합산될 위험이 있다. 굳이 한다면 플랫폼별로 ZIP을 분리해 업로드하고,
   각 ZIP이 개별적으로 1.44MB 이하가 되게 한다. (심사 해석 리스크가 있으니
   확신이 없으면 Windows 하나로 간다.)

4. **게임 제목·소개가 필수 항목이 아니다** — 즉 대충 내는 참가자가 많다는 뜻.
   **여기를 잘 쓰는 것만으로 차별화된다.** 소개문은 3~5문장으로 장르·조작·목표·
   기술적 자랑거리(용량)를 담아 미리 작성해둔다.

5. **국제 공모전이다 (한/영/일).**
   → 게임 내 텍스트는 **영어 기본** 또는 언어 비의존(아이콘·픽토그램) 설계가 안전하다.
   한글 폰트를 넣지 않아도 되니 **용량도 절약된다.** (`05-용량예산.md` 폰트 항목)

6. **수상작은 2P GAME ARCADE 전시회·행사에 전시될 수 있다.** ← 중요
   심사자는 "전시장에 놓을 수 있는 게임인가"를 의식할 가능성이 높다.
   → **전시 친화적 설계가 가산점.** `02-심사기준분석.md` 참고.

7. **저작권은 개발자 귀속**, 주최 측은 홍보·전시 목적 사용 가능. 불리한 조항 없음.
   단 **"사용 자료가 직접 제작되었거나 적절한 권리를 보유"함을 확인**해야 하므로
   외부 에셋 라이선스를 반드시 정리해둔다.

## FAQ (공식 원문)

**Q. 1.44MB는 정확히 어떻게 측정하나요?**
A. 3.5인치 HD 플로피의 실제 물리적 용량인 **1,474,560 바이트**를 기준으로 합니다.
   **압축 해제 후 기준**입니다.

**Q. 게임 내부 압축 사용이 가능한가요?**
A. 네. 단 **최종 실행 가능한 전체 크기**가 1,474,560 바이트 이하여야 합니다.

### FAQ가 확정해주는 것

1. **제출 ZIP 크기는 무의미하다.** 심사는 압축을 푼 폴더 기준.
   → ZIP으로 용량을 맞추려는 시도는 전부 헛수고.
2. **"게임 내부 압축"은 명시적으로 허용된다.** 에셋을 zlib/LZ4로 묶어 넣고
   런타임에 메모리에서 푸는 방식은 안전하다. 이건 디스크상 크기가 곧 최종 크기이기 때문.
   → **적극 활용할 것.** 텍스처·맵·폰트를 압축해 넣으면 실질 예산이 2~3배로 늘어난다.
3. **경계선은 "최종 실행 가능한 전체 크기".** 즉 게임을 돌리는 데 필요한 모든 파일의 합.
   → UPX 같은 실행파일 패커는 이 정의상 통과할 여지도 있지만,
   규칙 01의 "압축 해제 후"와 충돌한다. **리스크를 지지 말고 쓰지 않는다.**

## 규칙 해석 — 주의할 회색지대

1. **"압축 해제 후"의 의미**
   - 제출용 ZIP을 푼 결과 폴더의 총합이 기준. ZIP 크기는 무의미.
   - → **UPX 같은 실행파일 패커로 exe를 줄이는 꼼수는 안전하지 않다.** 패커는 "압축"이므로
     심사자가 언팩 후 크기를 잴 수도 있다. **보수적으로: 패킹 없이 순수 파일 합계로 통과시켜라.**
   - 반면 "게임 내부 압축"(에셋을 zlib으로 넣고 런타임에 푸는 것)은 FAQ에서 명시적으로 허용.
     이건 디스크상 크기가 이미 압축된 크기이고, 그게 최종 크기이므로 안전하다.

2. **측정 단위**
   - 1,474,560 바이트 = 1440 KiB. **1.44 MB ≠ 1,440,000 바이트가 아니다.**
   - 파일시스템 "디스크상 크기(클러스터 할당)"가 아니라 **실제 파일 크기 합계**로 계산하되,
     여유를 두기 위해 **목표는 1,400,000 바이트 이하**로 잡는다. (약 5% 안전 마진)

3. **동봉물도 용량에 포함되는가**
   - README, 조작법 txt, 아이콘 등도 폴더에 있으면 합산될 가능성이 높다.
   - → 조작법은 **게임 내 화면**으로 넣고, 폴더에는 exe + 최소 파일만 둔다.
   - 스크린샷·홍보물은 제출 폼에 따로 올리고 폴더에는 넣지 않는다.

4. **DirectX / VC++ 재배포 런타임**
   - 시스템에 기본 설치된 것(`kernel32`, `user32`, `d3d11`, `opengl32`)은 동봉 불필요 → 세이프.
   - `msvcp140.dll`, `vcruntime140.dll`을 동봉해야 하면 **정적 링크(/MT)로 전환**해서 제거.
