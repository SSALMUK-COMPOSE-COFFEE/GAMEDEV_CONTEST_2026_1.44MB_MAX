## 권장안

### 1순위 — **C + raylib 5.5 (config 트림 + GLFW + GL3.3, 정적 링크, `-Os`)** ← **확정**
- **실측 502,272 바이트**로 창/입력/오디오(XM+WAV)/텍스처/렌더타깃/폰트/2D카메라 전부 확보.
- **에셋 예산 972,288 바이트(한도의 66%)가 남는다** → 완성도에서 압도 가능.
- **Wine 실행 검증 통과** — 셰이더 컴파일, 텍스처 업로드, FBO 생성, 폰트 로딩 확인.
- 빌드 옵션 실측 교훈:
  - **`-Os` 사용** (`-O2`는 +68KB 손해, `-Oz`는 `-Os`와 동일해 이득 없음)
  - **config 트림 필수** (실사용 빌드에서 −107KB)
  - 손으로 코드 발췌는 무의미 — `--gc-sections`가 이미 오브젝트의 80%를 버린다
  - ❌ **`-DPLATFORM_DESKTOP_RGFW`는 −170KB를 주지만 크래시한다.** 채택 보류.
- 🔑 **교훈: 크기만 재고 엔진을 고르면 안 된다.** RGFW가 크기 1등이었으나 실행에 실패했다.
- 빌드 옵션: `-O2 -flto -s`(GCC/Clang) 또는 MSVC `/MT /O2 /GL /LTCG`, `/OPT:REF /OPT:ICF`
- 안 쓰는 모듈 제거: `SUPPORT_MODULE_RMODELS=OFF`, `SUPPORT_FILEFORMAT_*` 최소화 (config.h)

### 2순위 — **Zig 또는 Odin + raylib**
- 개발 속도와 안전성이 낫고 용량도 비슷. **단, 팀이 해당 언어에 익숙할 때만.**
- D-28에 새 언어를 배우는 건 리스크. 익숙한 걸 골라라.

### 3순위 — **순수 Win32 + 소프트웨어 렌더러**
- 20KB짜리 exe로 "1.44MB 중 겨우 30KB" 서사를 만들 수 있다 (기술적 자랑거리).
- 단 화면 흔들림·파티클·사운드 등 게임필을 전부 직접 구현해야 함 → **시간 리스크 큼.**
